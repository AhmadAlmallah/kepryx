# Kepryx QA report

Evidence date: 2026-08-28 | Candidate: v0.9.0 community preview | Reviewer: Ahmad Almallah

## Executive result

The exact staged candidate passed the automated quality gates and the selected live acceptance
checks. It is suitable for a private-first open-source preview. It is not presented as a fully
production-proven enterprise release because measured application coverage is 53.63%, several
browser-only workflows still need manual expansion, and real external-provider and HA evidence is
not available in this local environment.

## Scope and evidence model

The review covered Python application code, frontend static assets, Compose configuration, Docker
builds, migrations, deterministic fixtures, the live local stack, and release documentation.
Documentation was treated as a hypothesis; pass statements below map to executable tests, commands,
or live API/browser observations.

## Browser evidence

The local browser smoke loaded all 16 operator views without the previous `children.filter is not
a function` failure. The graph controls were operated against live API-backed state. The evidence
record is [BROWSER-MUTATION-EVIDENCE.md](BROWSER-MUTATION-EVIDENCE.md). Remaining browser expansion:
multipart import, exports, GDPR, compliance drill-down, and the advisory AI modal.

## Coverage interpretation

53.63% is an honest release signal, not a claim that the application is 53.63% secure. Stronger
coverage exists around risk, password policy, API mutations, scanner authorization/parsing, CVE
enrichment, reconciliation, connector contracts, self-security, assistant safety, webhooks, and
worker policy. The largest remaining value is end-to-end browser mutation and failure-injection
coverage, followed by representative legacy-data migrations and provider contract tests.

## Residual QA risks

| ID | Residual risk | Severity | Release treatment |
|---|---|---|---|
| QA-01 | Deep browser mutation does not cover every operator screen | Medium | Disclose; keep API integration tests as the current safety net |
| QA-02 | 53.63% coverage leaves untested branches | Medium | Keep 50% CI floor; raise coverage incrementally after preview feedback |
| QA-03 | Real provider rate limits, schema drift, and credential failures are not tested with customer accounts | Medium | Use vendor-neutral fixture; require provider-specific staging tests |
| QA-04 | Load, soak, failover, and production restore are not proven | Medium | Treat Compose as single-host preview; require an operational pilot before production |
| QA-05 | Scan authorization is synthetic in this evidence set | High operational boundary | Require written customer-owned CIDR approval before any real scan |
| QA-06 | Old orphan containers exist on the local Docker host outside canonical Compose | Low local hygiene | Do not include them in release claims; remove only by explicit operator decision |

## QA conclusion

The candidate is testable and demonstrable at community-preview scope. The test suite and live
acceptance evidence support publishing as v0.9.0 preview material. The report does not support the
stronger claim “fully production ready” until the residual risks above have evidence.
